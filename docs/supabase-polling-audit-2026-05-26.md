# Supabase Load Audit — Nearify Web

Date: 2026-05-26

## Scope searched
`setInterval(`, `setTimeout(`, `messages`, `conversations`, `event_attendees`, `events`, `getSession(`, `onAuthStateChange(`, `realtime`, `channel(`, `subscribe(`, `refresh`, `polling`, `invalidate`, `refetch`.

## Executive summary
- **No direct web code path currently querying `messages` or `conversations`** (no `.from("messages")` / `.from("conversations")` matches in this repo).
- Highest recurring load offender is **guest live attendee polling** in `join.js` against `get_public_event_attendees` (RPC over `event_attendees`) every ~60–75s per open tab.
- Next largest risk is **auth-driven duplicate dashboard reloads** caused by parallel `onAuthStateChange` handlers across modules and repeated full refresh chains.
- There are currently **no active `channel().subscribe()` realtime subscriptions** in production web code; helpers exist but are not used.
- Hidden-tab behavior is partially handled for guest polling (`document.hidden` short-circuit), but timer still reschedules while hidden.

## Findings by endpoint/table

### `/rest/v1/messages`
- **Observed source in this repo:** none.
- **Likely conclusion:** request volume for this endpoint is not generated by current Nearify Web codebase snapshot.

### `/rest/v1/conversations`
- **Observed source in this repo:** none.
- **Likely conclusion:** request volume for this endpoint is not generated by current Nearify Web codebase snapshot.

### `/rest/v1/event_attendees`
1) `events/index.html` loads all attendees for all listed events in one query on every page load.
2) `dashboard.js` performs two aggregate queries over `event_attendees` each dashboard load/refresh.
3) `eventDetail.js` attendee discovery + intelligence reads `event_attendees` at least twice per page load for signed-in users.
4) `join.js` live polling repeatedly calls RPC `get_public_event_attendees` every 60–75s plus foreground refresh.

### `/rest/v1/events`
1) `events.js` public/organizer event fetches (`fetchPublicEvents`, `fetchOrganizerEvents`, `saveEvent` paths).
2) `eventDetail.js` event fetch by `id`/`slug`, plus event meta load for intelligence.
3) `join.js` event bootstrap query from `events`.

## Polling loops inventory
- `assets/js/join.js`: `schedulePoll -> setTimeout(runPoll, 60000 + jitter up to 15000)`.
- Cleanup exists (`stopLivePolling`) but duplicate loop risk remains due to missing idempotent `startLivePolling` guard.

## Realtime subscriptions inventory
- No current `channel(...).subscribe(...)` call sites in app code.
- `supabaseLoad.js` contains reusable realtime registry helpers not currently wired.

## Ranked highest-load offenders (estimated impact)
1. Guest live polling (`join.js`): **35–60% reduction**.
2. Dashboard refresh chains (`dashboard.js`): **15–30% reduction**.
3. Events listing attendee meta (`events/index.html`): **10–20% reduction**.
4. Auth fan-out (`navAuth.js` + page modules): **5–15% reduction**.

## Minimal targeted fixes (no architecture rewrite)
1) Add idempotent polling start guard in `join.js`.
2) Pause timer (not only query body) while hidden; restart on visible.
3) Dedupe `loadDashboard`/`refreshDashboard` in-flight.
4) Skip redundant profile fetches in `navAuth.js` for unchanged user.
5) Add short TTL cache for attendee meta on events listing.
